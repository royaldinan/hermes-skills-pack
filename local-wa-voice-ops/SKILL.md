# Local WA + Voice Ops

## Overview

Local assistants with Backend + WA bridge + GPU voice agent fail in
predictable ways: stale code, zombie sockets, swallowed probes, and
whole-file audio metrics. Follow the order below.

## Procedure

1. Map processes first: list PIDs bound to each port before touching code.
2. Enforce single instance per device-linked bridge before diagnosing logic.
3. Verify restart after every patch: PID and start time must change.
4. Probe with unique payloads, then read server-side logs.
5. Gate voice output on speech-segment metrics, never whole-file averages.
6. Keep one smart voice profile; never stack pitch + tempo + long text.
7. Free VRAM before GPU training: stop the voice agent first, then resume training.
8. Resume GPT-SoVITS training by raising epoch caps, never from scratch.

## Rules

- Kill Windows Node zombies with taskkill /F /PID — process.kill SIGKILL is a silent no-op on Windows and leaves the old socket holding the session.
- Auto-restart Baileys on status 401 (loggedOut): wiping auth_info_baileys without immediately invoking connectToWhatsApp() kills the socket silently; the stale QR image remains frozen on disk and any device scan fails with "Gagal menautkan perangkat", while /pair returns 428 Connection Closed. Always trigger setTimeout(connectToWhatsApp, 2500) after cleanup so a live socket awaits the scan.
- Fast-track Baileys reconnect on status 515 (restartRequired) to 1000ms: during device linking, WhatsApp server drops the initial socket to switch encryption keys; a delay >2s causes the phone's linking screen to time out and display "Gagal menautkan perangkat".
- Use Browsers.macOS('Safari') or Browsers.ubuntu('Chrome') for Baileys: Browsers.windows('Desktop') triggers client signature rejection on newer WhatsApp Web protocols during QR/pairing handshakes.
- Keep one bridge instance per linked device — two node.exe with one device ID cause 440 connectionReplaced reconnect loops.
- Support both Pydantic v1 and v2 in FastAPI models: system or embedded venvs may run Pydantic 1.10 where .model_dump() raises AttributeError; use `data = obj.model_dump(...) if hasattr(obj, 'model_dump') else obj.dict(...)`.
- Override onReceivedSslError in Android WebView wrappers: default WebViewClient cancels SSL errors silently, producing a blank black screen without firing onReceivedError; always implement handler.proceed() and enable WebView.setWebContentsDebuggingEnabled(true) with console message forwarding.
- Measure speech segments, not whole files: VAD-gate first, then RMS/peak/ZCR on speech only, because long silence dilutes whole-file averages into false quiet/robot readings.
- Reject silent renders before sending: silence ratio above 0.85 or speech RMS below 0.02 means failed render, do not ship it as VN.
- Use one smart emotion profile driven by text and user tone — parallel happy/sad/angry chains drift out of sync and multiply pitch/tempo stacking into robotic output.
- Check RAM/GPU pressure when voice slows 4s into 10s — high memory forces fallback paths and longer chunked renders.
- Report verified root cause plus plan in plain text before executing when diagnosis-first was asked — jumping straight to fixes breaks trust even when the fix is right.
- Gate renders on speech-segment metrics (RMS/peak/ZCR/silence plus VAD groups vs known-good clips) to prove healthy audio only — RMS/peak/silence measure volume and pauses and are blind to speaker similarity and metallic artifacts, so the similarity verdict is the user's ear or speaker-embedding cosine, never the metric band.
- Always close a tool batch with a processed result — an empty reply after tool calls strands the session and forces the user to re-prompt.
- Rebuild OmniVoice voice-clone prompts from dry HDemucs vocals with the exact verified transcript — raw YouTube audio bakes BGM/reverb into the embedding as metallic buzz, and mismatched ref_text breaks phoneme alignment.
- Verify timestamp arithmetic before attributing legacy log traces: converting millisecond timestamps (e.g. 1789... vs 1790...) to datetime prevents attributing older legacy runs (Edge-TTS+RVC) to current-day diffusion renders; check sample rates (24kHz = pure OmniVoice vs 48kHz = RVC) and duration parity (~40ms tolerance) to prove zero-shot diffusion origin mathematically.
- Never stack RVC or lowpass filters on top of pure OmniVoice diffusion: OmniVoice diffusion already maps emotional prosody and timbre; running RMVPE pitch estimation on top breaks natural pitch contours, and lowpass filters (<10kHz) muffle breath sparkle and vocal presence into a boxy drone.
- Never substitute cloud Whisper Large v3 Turbo with local CPU faster-whisper-base for room/far-field mic input: a 74M-param base model on CPU hallucinates phonetic sound-alikes on low-energy or regional accents (e.g. Indonesian religious phrases -> random personal names), triggering false intent execution. Always prioritize Groq Whisper Large v3 Turbo with domain keyword prompt biasing.
- Cap spoken character voice notes to 50–70 characters (6–10s): diffusion models (OmniVoice) degrade into flat, breathless, marathon drones when synthesizing 150+ character paragraphs (e.g. technical system/clipboard status); translate only the concise emotional essence for audio, while keeping visual subtitles detailed.
- Lock synthesis to mahiru_prompt_6s.wav when authentic studio calmness is required: pre-computed emotion prompt tensors (e.g. prompt_cheerful.pt) can shift mean F0 pitch too high (>370-410Hz) and sound shrill/screechy compared to the authentic studio master (F0 ~320-340Hz).
- Sanitize PYTHONPATH when launching sub-processes across different virtual environments on Windows: an exported PYTHONPATH pointing to Python 3.11 site-packages leaks incompatible binary wheels into Python 3.10 (rvc_env), causing silent C-extension failures (_imaging, _pydantic_core, _multiarray_umath). Always run env.pop('PYTHONPATH', None) or set PYTHONPATH= in startup batch scripts.
- After swapping a prompt .pt, prove the agent loaded it: prompt mtime must predate agent PID start time, the log must show Loaded voice prompt for that emotion, plus a live POST probe returns 200 — a file on disk alone proves nothing.
- Drop GPT-SoVITS S1 batch_size to 2 on 6GB VRAM — the 77.6M Text2SemanticDecoder OOMs at batch 4 even with AMP; a smaller batch only adds per-step gradient noise and wall-clock time, never final voice quality, so quality promises rest on data minutes and epochs, not batch size.
- Resume GPT-SoVITS by raising epochs in output/<exp>/train_s1.yaml (epochs) and train_s2.json (train.epochs) to the TOTAL target count, never the remaining count — a value at/below the loaded checkpoint's epoch makes the trainer print 'training done' with zero steps, so the run looks successful while training nothing.
- Prepare a new GPT-SoVITS v2 experiment with a .list file plus 1-get-text plus 2-get-hubert-wav32k plus 3-get-semantic, then merge partition outputs into 2-name2text.txt and 6-name2semantic.tsv — list rows are wavpath|speaker|lang|text, each script takes env vars (inp_text, inp_wav_dir, exp_name, i_part/all_parts, opt_dir plus its model dir), an empty 3-bert dir is normal for non-Chinese text since BERT features save only when lan==zh, and 3-get-semantic crashes with duplicate version kwarg unless the version key is removed from train_s2.json's model section because SynthesizerTrn already receives version explicitly — but keep version in the config used for s2_train (use a separate copy for the semantic step), because s2_train reads hps.model.version and crashes without it.
- Deploy new GPT-SoVITS weights by pointing GPT_SoVITS/configs/tts_infer.yaml custom t2s_weights_path at GPT_weights_v2/<exp>-eN.ckpt and vits_weights_path at SoVITS_weights_v2/<exp>_eM_s*.pth, then render one verification mp3 and report duration plus speech-segment metrics — a ckpt file on disk alone proves nothing until it synthesizes.
- Gate production swaps on A/B renders (old vs new weights, same ref audio, JP plus ID text) scored by f0 band-share plus the user's ear — a 10x-larger auto-diarized dataset can tie or lose to a small clean baseline because diarization+f0 leaks other speakers, BGM, and SFX into the training set, so keep the baseline live until the new model wins both numbers and listening.
- Never rate a third-party voice model from download counts or model cards — a multi-character model (two roles, one speaker) bakes both timbres together with no clean split, so download it, note any per-speaker IDs from its description, render test clips, and let the ear decide before replacing anything.
- Download NLTK averaged_perceptron_tagger_eng plus averaged_perceptron_tagger into rvc_env before GPT-SoVITS inference on English/Indonesian text — the G2P path raises LookupError at synthesize time when the tagger data is absent, so the one-time download belongs before the first A/B run, not after it fails.
- Audit the training set via output/<exp>/mahiru_clean.list plus mahiru_slices total duration before promising voice quality — multi-speaker slices and minute-scale totals cap quality no matter how long training runs.
- Import pytorch_lightning, not lightning, in rvc_env — the venv ships pytorch_lightning 2.x with no lightning alias and no pip module, so probe imports with the venv python before writing training code.
- Triage Windows VRAM with nvidia-smi plus --query-compute-apps before training — WDDM reports per-process usage as N/A, so list PIDs explicitly and kill useless GPU holders (game launchers, overlay renderers, lingering blender.exe from finished headless renders) before starting; freed VRAM must read near-zero used.
- Check free disk space before multi-hour training runs — torch.save writes 500MB+ checkpoints and fails mid-write with zip/inline_container errors on a nearly-full disk, killing the run at save time after hours of compute; keep free space several times the checkpoint size.
- Cap epoch expectations to dataset size — ~2min of slices pushed to 50 epochs renders louder-than-reference RMS (overfit signal), so report the loudness delta honestly and collect 10-20min clean single-speaker audio before promising similarity.
- Prefer python one-liners over complex PowerShell quoting from bash — nested quoting breaks silently under MSYS while python file ops are exact.
- Evaluate training renders with f0mean/f0std (librosa.yin 50-600Hz) against known-good refs — MFCC-mean plus RMS/silence are blind to flat prosody and pitch drop, so report pitch delta and loudness delta; pitch down tens of Hz with RMS near 2x means overfit, never similarity. Add p5/p95 plus the share of voiced frames inside the character's f0 band (e.g. 300-450Hz) — low band-share with normal std means the voice sits in the wrong register, not flat prosody. Probe both JP and ID texts because the two paths use different Edge voices and RVC pitch_shift.
- Never present spectrogram or MFCC analysis as listening — the agent has no hearing, vision of spectrograms plus numbers is triage only and the similarity verdict stays with the user's ear or speaker-embedding cosine.
- When endpoint renders truncate but direct renders of the same text stay healthy, blame the serving path first — verify both paths before retraining or declaring the model broken.
- Triage multi-speaker stock with an f0 histogram before promising dataset size — bimodal low-plus-high bins mean mixed speakers, so count only segments inside the character's f0 band toward clean single-speaker minutes.
- Single-server entry is START_MAHIRU.bat (backend 8000 serves frontend plus autostarts 8001/8002 when ports are free) — never start agent_server.py or node server.js manually alongside it or ports/VRAM collide; STOP_MAHIRU.bat kills all three ports plus bridge PID files.
- When the UI shows text none of your tool calls produced, grep the repo, scratch, and session history for the mystery string before theorizing — zero hits everywhere proves foreign render or cross-session bleed, not your action, so say so plainly and move on.
- Restore the last known-good voice pipeline as production baseline before any retrain, gated behind an env flag defaulting to baseline — baseline recipe is Edge-TTS ja-JP-NanamiNeural +8Hz/+0% (JP) and id-ID-GadisNeural +16Hz/+2% (ID) into RVC with pitch_shift 0 JP / 1 ID and index 0.85, because autostart relaunches the same file and an unconditional experimental path orphans the working pipeline.
- Reconfigure stdout/stderr to UTF-8 at the top of any pythonw-launched server before the first print — pythonw without a console defaults to cp1252 and an emoji print raises UnicodeEncodeError that kills the process silently under autostart.
- After taskkill of the voice agent, confirm the port is FREE with netstat before any manual start — backend ensure_services_running autostarts 8001/8002 only once at its own boot, not on a loop, so no respawn race exists later; a stale LISTENING socket is the real collision risk on port and VRAM.
- Verify episode identity from inside the container before rejecting user-supplied files — ffprobe format title tag plus character names in the subtitle track prove the anime, because uploader filename prefixes are unreliable and a mislabeled file can still be the right source; rejecting on filename alone discards valid training stock.
- When the training venv ships without pip, never repair it in place — create a sidecar curation venv with uv venv plus --seed and a pinned Python, then install deps there, because forcing pip into the working training env risks breaking the pipeline that already trains.
- Isolate one female voice from multi-speaker anime stock with pyannote.audio diarization plus SpeechBrain ECAPA embeddings — ECAPA separates two female voices that f0-band filtering and resemblyzer conflate, and the gated models need only a free HuggingFace account with accepted licenses plus a Read token; run curation with the voice agent stopped so limited VRAM is fully free.
- Triage gated-repo 403s with HfApi().model_info on each required repo before touching auth code — license-accept clicks propagate with delay, so persist the login with login(token) and retry after re-verification instead of rewriting the auth plumbing on the first failure.
- Feed pyannote pipelines a preloaded waveform dict when torchcodec is broken on Windows — load with soundfile into a (channel, time) torch tensor and call pipeline({"waveform": waveform, "sample_rate": sr}), because the built-in decoder raises RuntimeError while the models themselves run fine.
- Read diarization turns from diar.speaker_diarization.itertracks(yield_label=True) — the DiarizeOutput wrapper in pyannote.audio 4.x exposes no itertracks of its own, so iterating it directly raises AttributeError after an otherwise successful run.
- Re-verify torch.cuda.is_available() after every pip install into a CUDA sidecar venv and force-reinstall the cu121 torch/torchaudio wheels with --no-deps when it flips — plain dependency resolution pulls a CPU torch wheel that silently replaces the GPU build and every later GPU step crawls or OOMs.
- Drop webrtcvad from the curation install list when no MSVC Build Tools exist — its wheel needs a C++ compiler to build and pyannote already covers VAD, so chasing a compiler wastes an hour for a redundant package.
- Build the single-speaker training set from diarized vocals by scoring f0 per speaker per episode — pick the longest-duration speaker inside the character's f0 band (e.g. 300-430Hz with band-share >= 0.25), merge same-speaker turns with gap under 0.4s into 1-12s clips, drop near-silent clips (RMS under 0.01), then spot-check random clips for f0/RMS before training — diarization labels shift per file but the duration-dominant voice in the right band is stable across episodes.
- Start background servers with cd 'path' && python in the command body when the project path contains parentheses — the terminal workdir field rejects shell metacharacters, so a cd prefix is the invocation that actually launches.
- Register the torch lib dir with os.add_dll_directory before importing faster-whisper on Windows — ctranslate2 loads cublas64_12.dll lazily at transcribe time and fails even when the DLL ships with torch, so the script itself must add torch/lib to the DLL search path, not the shell.
- Transcribe long clip sets with a resume-safe TSV writer (header once, flush per row, skip files already listed) and prefer the cached faster-whisper model variant — prove progress by TSV line-count growth, because a dropped connection otherwise restarts hundreds of clips from zero and a missing model pulls gigabytes mid-run.
- Auto-diarized anime datasets (pyannote + demucs + f0 filter) routinely lose to small clean baselines in A/B voice quality — diarization leaks co-speaker segments, BGM, SFX, and compressed-audio artifacts into training clips, so a 27-minute auto-diarized set can produce more robotic output than 24 hand-curated clips; report band energy (target 0.39-0.50) and f0 band-share alongside f0 median — low band energy (0.10-0.14) means the vocoder failed to capture brightness regardless of dataset size.
- Evaluate third-party RVC voice models by rendering test audio, never by download count or model card claims — a multi-character model bakes both timbres together with no clean split; note per-speaker IDs from the description page, render probes via BaseLoader, and let the ear decide before replacing baseline.
- Use infer_rvc_python BaseLoader (not configs.config + VC from RVC source) for inference-only multi-model tests: apply_conf(tag, file_model, pitch_algo, pitch_lvl, file_index, index_influence, respiration_median_filtering, envelope_ratio, consonant_breath_protection, resample_sr) then result = generate_from_cache(audio_data, tag) — result is (np.ndarray_int16, sample_rate), NOT (sr, array); convert with audio.astype(np.float32)/32768.0 before sf.write; there is no output_path or overwrite parameter; configs.config only exists when the full RVC repo is present as a directory.
- Never write RVC test scripts to $TMPDIR via bash heredoc when invoking with native python.exe — MSYS $TMPDIR does not translate to a Windows path for native executables, so python.exe raises 'No such file'; write scripts to an explicit Windows path like C:/Users/User/Documents/Personal/test.py instead.
- Run Python diagnostic and comparison scripts foreground (not background) when root-causing failures — background processes swallow tracebacks and produce silent 'DONE' that looks like success; run foreground so every error line is visible in real time before concluding what failed.
- Trim OmniVoice onset murmur blips before RVC conversion: autoregressive diffusion models generate a 100–300ms onset burst followed by an RMS energy valley (<0.006) before speech begins; slice the audio at speech onset (>0.015 RMS) with a 20ms cosine fade-in, otherwise downstream RVC turns the burst into an audible 'yoo...' or breath artifact.
- Sanitize Latin words, foreign titles, emojis, and unescaped HTML entities in Japanese TTS text: neural tokenizers choke on raw Latin words (e.g. 'YouTube', 'Memories'), triggering phoneme stuttering and pitch glitches unless mapped to Katakana ('ユーチューブ', 'メモリーズ') and stripped of emojis and trailing glottal stops before synthesis.
- Parse task priority tokens (p1-p4, prioritas 1-4) with explicit precedence flags: never use max(priority, default_priority) in action handlers because it permanently locks low-priority requests (P1) to the default (P2).
- Use single-breath joint generation for WhatsApp voice notes (reply + japanese_voice generated together in one LLM turn): generating visual text first and translating in a second pass adds 15–25s latency and causes the short-stub bypass trap where 24-character stubs skip translation, leaving VN clips only 3s long for multi-paragraph messages.
- Civitai voice model API (api/v1/models?types=Other) returns empty JSON for voice models — use the browser at civitai.com/search/models or civitai.com/tag/<name> and filter by type manually; CivArchive mirrors metadata but does not provide download links for deleted/unlisted models.
